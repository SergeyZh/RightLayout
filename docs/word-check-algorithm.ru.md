# Как RightLayout решает, переключать ли слово

Описание составлено по коду ветки `main` на конец октября 2026 года (коммит `e877c0b`). Первая версия описывала код сразу после подключения частотных словарей ([PR #4](https://github.com/SergeyZh/RightLayout/pull/4)); что поменялось с тех пор, собрано в разделе 8. Ссылки на код даны в виде `файл:строка` относительно `RightLayout/Sources/`.

## 1. Источники знаний

Движок опирается на шесть источников. Все они отвечают на вопрос «похоже ли это на настоящее слово языка X».

| Источник | Что это | Как используется |
|---|---|---|
| **Встроенный лексикон** | Ручные списки слов в `Resources/language_data.json` (`lexicon.russian/english/hebrew`) | `BuiltinWordValidator`: доля слов фразы, найденных в списке (0…1). Самый надёжный сигнал. |
| **Частотные словари** | `ru/en/he_unigrams.tsv`, топ‑200 000 слов на язык с числом употреблений | `WordFrequencyModel`: частотная оценка 0…1 и признак «слово есть в списке». |
| **Системная проверка орфографии** | `NSSpellChecker` macOS | `SystemWordValidator`: доля слов без ошибок. Словарь языка, который принимает заведомую бессмыслицу (иврит), отключается. |
| **Триграммная модель** | `*_trigrams.json`, вероятности трёх букв подряд | Насколько строка «звучит» как язык, даже если слова нет в словарях. |
| **CoreML‑классификатор** | `LayoutClassifier.mlmodel` | Предсказывает гипотезу раскладки (`ru`, `en_from_ru`, `ru_from_en` …) и уверенность. |
| **Белые списки** | `language_data.json` (whitelist, zeroInterference, короткие слова иврита) | Слова, которые нельзя трогать или которые надо узнавать сразу. |

Кроме них есть два коротких списка, которые используются в обход всех оценок (раздел 3):
- **сокращения и смайлики** (`Core/WrongLayoutShorthand.swift`): «т.е.», «т.к.», «т.д.», «и.о.», «к.т.н.» и т. п.; «:)», «:-)», «;)», «:D», «:-P» и т. п.;
- **русские слова из одной буквы** (`CorrectionEngine.singleLetterWords`): «а», «в», «и», «к», «о», «с», «у», «я»; английские: «a», «i».

### 1.1. Частотные словари

Загрузка: `Core/WordFrequencyModel.swift`.

1. Файл ищется в корне ресурсного бандла (SwiftPM складывает туда всё содержимое `Resources/LanguageModels`), а если его там нет, в подпапке `LanguageModels`. В собранном `.app` ресурсный бандл лежит в `Contents/Resources` (`Bundle.rightLayoutResources`, `Core/ResourceBundle.swift`).
2. Каждый язык разбирается **один раз на процесс** (`WordFrequencyModel.shared("ru")`), и все компоненты движка пользуются одной копией.
3. Строки вида `слово<TAB>число`. Слово приводится к нижнему регистру, хранится `ln(1 + число)`.
4. **Слова короче 3 букв отбрасываются.** Среди них почти один мусор и сокращения («пп», «gg», «cj», «bp»), а на коротких словах раскладки чаще всего совпадают. Короткие настоящие слова («из», «со», «на») есть во встроенном лексиконе.
5. Частотная оценка слова: `score = ln(1 + count) / ln(1 + count_самого_частого)`, от 0 до 1. Неизвестное слово даёт 0.

Примеры (ru): «на» = 1.0 (самое частое), «привет» ≈ 0.66, «сожалению» ≈ 0.49, «избиратель» ≈ 0.25, «раскладка» ≈ 0.34.

Как частотный словарь участвует в решении:
- **как проверка «слово существует»** (`BundledWordValidator`, `Core/WordValidator.swift:161`): доля слов фразы, которые есть в списке. Входит в `HybridWordValidator` = максимум из системной проверки, частотного словаря, встроенного лексикона и белого списка. Поэтому «слово известно» означает «есть хотя бы в одном из этих источников»;
- **как частотность** (`frequencyScore` в роутере, `fastWordScore` в движке, `wordScore` в верификаторе): среднее по словам фразы значение `score`. Для английского в `fastWordScore` учитываются только оценки ≥ 0.20, чтобы редкие «слова»‑опечатки не мешали;
- **как признак «слово, набранное через клавиши знаков»** (раздел 6.2): если слово со знаками внутри после конвертации целиком есть в частотном словаре («Yf;fk» → «нажал»), оно конвертируется целиком.

## 2. Когда запускается проверка

`EventMonitor` копит набранные символы текущего слова. Граница слова — только пробельный символ (пробел, Enter). Знаки препинания остаются частью слова («Lf/», «ghbdtn.rfr»), их разбирает движок.

1. **Пауза не обрывает слово.** Раньше после 2 с без нажатий (`bufferTimeout`) набранное начало слова выбрасывалось, и проверялся только хвост, а слово, законченное после паузы, не проверялось вовсе. Теперь слово сохраняется. Сбрасывают его только клик, смена фокуса и сочетания клавиш, которые могут сдвинуть курсор.
2. **Задержка Enter.** Если слово закончено Enter (настройка «Не отправлять Enter, если слово нужно исправить», по умолчанию включена), Enter придерживается, пока слово проверяется, чтобы сообщение в чате не ушло с ошибкой. Если слово не исправлено, Enter отправляется сразу; если проверка заняла больше 0,5 с, Enter отправляется, а исправление отменяется. Если слово исправлено, Enter не отправляется: пользователь видит исправленный текст, и его следующий Enter проходит без задержки. Если движок предложил только подсказку, при задержанном Enter она применяется сразу: другого слова, которое подтвердило бы язык, уже не будет.
3. **Сверка с полем.** Перед заменой монитор читает текст поля (Accessibility) и сверяет его с набранным словом. Если приложение отстаёт от нажатий (Slack в длинном сообщении), поле перечитывается дольше обычного, ещё до ~0,25 с. Если оказалось, что буфер содержит только конец слова (перед ним в поле стоит буква или цифра — так бывает после смены фокуса), слово не исправляется: исправленный хвост сломал бы слово («всякийс лучай» превращалось в «всякийc kexfq»).

Затем монитор вызывает `CorrectionEngine.planCorrection` → `correctText(слово)` (`Engine/CorrectionEngine+Decide.swift:11`). Ответ движка превращается в план: заменить автоматически, показать подсказку, оставить для ручного переключения по горячей клавише, или ничего не делать.

## 3. Предварительные отсечения в движке

`correctTextUnrestricted` (`CorrectionEngine+Decide.swift:61`):

1. Пустая строка или пробелы: ничего не делать.
2. Слово из списка **zeroInterference** (международные термины): не трогать.
3. **Сокращение или смайлик в чужой раскладке** (`shorthandCorrection`, строка 1067). Языковые модели такие токены оценить не могут, поэтому проверяется точное совпадение с коротким списком (2…12 символов, хотя бы одна буква):
   - русское сокращение, набранное в английской раскладке: «n/r/» → «т.к.». В токене должен быть «/», а результат — кончаться точкой: «n/r» без точки может быть английским сокращением;
   - смайлик, набранный в русской или ивритской раскладке: «Ж-)» → «:-)». Раскладка при этом не переключается: смайлик не принадлежит языку.

   Совпадение заменяется сразу, с уверенностью 1.0, без роутера и политики.
4. **Русское слово из одной буквы в английской раскладке** (`singleRussianLetterWord`, строка 1131). Одна латинская буква, которая не является английским словом («a», «i») и превращается в однобуквенное русское слово, исправляется сразу (уверенность 0.95), а раскладка переключается до следующего слова:
   - строчная — сразу после русского слова: «Прочитай b» → «Прочитай и» (раскладку переключили ради «@» и забыли вернуть);
   - заглавная в начале предложения после русского слова: «Привет. Z» → «Привет. Я»;
   - заглавная в самом начале текста — только если русский выбран предпочтительным языком и минимальная длина слова в настройках 1 буква: «Z» → «Я», «E» → «У».

   Заглавная внутри предложения остаётся как есть («план B», «витамин E»). Правило работает только при минимальной длине слова не больше умолчания (2 буквы), не в консервативном режиме и только если включены русский и английский.
5. **Детектор намерения** (`IntentDetector`): код, URL или команда — не трогать. Слово без пробелов со «/» считается путём, **кроме случая, когда косые черты стоят только в конце после букв**: «/» — это точка в русской PC‑раскладке, и «Lf/» — это «Да.».
6. Контекст: язык последней сделанной коррекции передаётся роутеру как подсказка.

Дальше вызывается роутер: `ConfidenceRouter.decisionEvidence(слово)`.

## 4. Роутер: какая это раскладка и какой язык

`ConfidenceRouter.route` (`Core/ConfidenceRouter.swift:230`) возвращает решение: гипотезу (`ru`, `en`, `he` — «набрано правильно», или `ru_from_en`, `en_from_ru`, `he_from_en`, `en_from_he`, `he_from_ru`, `ru_from_he` — «набрано не в той раскладке») и уверенность 0…1. Проверки идут в таком порядке, первая сработавшая возвращает ответ.

### 4.1. Жёсткие правила

1. **Пользовательский словарь** (`UserDictionary`): «оставлять как есть» → решение «как набрано» с уверенностью 1.0 (в ручном режиме правило снимается); «предпочитать гипотезу X» → сразу X.
2. **Одна буква** в автоматическом режиме: кириллица или иврит остаются как есть. Латинская буква остаётся как есть, если только она не превращается в русский предлог («y» → «н», «c» → «с» и т. п.). (Однобуквенные русские слова после русского текста движок исправляет ещё до роутера, см. раздел 3.)
3. **Смесь алфавитов** в одном слове («hello мир» без пробела): не трогать.
4. **Технический токен** (путь, UUID, версия, число‑метка): не трогать.
5. **Белый список**: слово узнаётся как слово своего языка и не трогается.
6. **Защита русского**: если слово написано кириллицей и `HybridWordValidator` для русского даёт ≥ 0.80 (слово есть в системном словаре, в частотном словаре или во встроенном лексиконе), это русское слово, переключать не нужно.

### 4.2. Шаг 0: оценочное решение (`scoredDecision`, строка 1258)

Детерминированный перебор всех вариантов.

1. **Оценка «как набрано»** в каждом языке: `quality(слово, язык)`.
2. Для каждой разрешённой гипотезы «X из раскладки Y» (только если алфавит слова совпадает с исходной раскладкой) строятся **все варианты конвертации** (`LayoutMapper.convertAllVariants`): через активную раскладку языка и через другие раскладки того же языка (PC/Mac, Hebrew/Hebrew‑QWERTY и т. д.).
   - **Раскладки с переставленными буквами** — фонетическая «Russian – QWERTY», Colemak, Dvorak (`LayoutMapper.rearrangedLetterLayoutIds`) — пробуются, только если это активная раскладка или она включена в macOS. Иначе получалась бы транслитерация или бессмыслица, случайно совпавшая со словом («privet» → «привет», «Саммари» → «Sammari», «пзе» → «ily»). Раньше так отсекалась только фонетическая раскладка и только для английского текста.
   - Если в слове есть «.» или «,» между буквами, дополнительно пробуется вариант, где они оставлены как разделители («ghbdtn.rfr» → «привет.как»).
   - **Знаки препинания** при конвертации переводятся по клавише, если и в целевой раскладке на ней знак препинания: «?» на US — это Shift+/, то есть запятая в русской PC‑раскладке («Lf?» → «Да,»), а «?» в русской PC — это Shift+7 и остаётся «?», а не становится «&».
3. Каждый вариант получает оценку:

   ```
   quality = A·W + B·F + C·N
     W — HybridWordValidator (словарь/лексикон/орфография), 0…1
     F — частотная оценка по частотному словарю, 0…1
     N — нормированная триграммная оценка, 0…1
     для слов ≤ 3 букв: A = 1.6, B = 1.6, C = 0
     для длинных:       A = 1.2, B = 1.0, C = 0.6
   ```

   К этому добавляются поправки: −0.05 (общий штраф за исправление), приоритеты гипотез (HE→RU +0.06, HE→EN +0.08, RU→HE −0.28), +0.35 для русского, если запятая или точка в исходнике стали буквами «б»/«ю» и результат похож на слово, +0.45 для частых коротких слов иврита.
4. Лучший кандидат выбирается так: **«сильное принятие»** (результат есть во встроенном лексиконе, а исходник нет) побеждает всех остальных. Между двумя сильными решает триграммная модель, потом `quality`. Иначе побеждает больший `quality`.
5. Особый случай для ивритского текста, который может оказаться английским или русским, набранным в Hebrew‑QWERTY: учитывается, насколько исходное ивритское слово само по себе частотное и известное.
6. Кандидат принимается, только если `quality(кандидат) ≥ quality(лучший «как набрано») + запас` (запас 0.25 для слов ≤ 3 букв, 0.70 для длинных, для иврита меньше) **и** W кандидата ≥ 0.80. Тогда уверенность решения 0.95.
7. Если уверенность ≥ `standardPathThreshold` (по умолчанию 0.70), роутер возвращает это решение сразу.

**Где сказываются словари.** Частое настоящее слово получает W = 1 и заметный F, поэтому «ghbdtn» → «привет» (F ≈ 0.66) выигрывает с большим запасом. Но и исходник, если он оказался словом в другом языке, тоже получает высокое «как набрано» и защищён.

### 4.3. Шаг 1: быстрый и стандартный путь

1. **Быстрый путь** (слова ≥ 4 символов): триграммные модели трёх языков. Если лучший язык совпадает с алфавитом слова, `HybridWordValidator` ≥ 0.80 и уверенность ≥ `fastPathThreshold` (0.95), это базовое решение «набрано правильно».
2. Иначе **ансамбль** (`LanguageEnsemble`: n‑граммы, NaturalLanguage, проверка слов) даёт базовое решение.
3. Если базовое решение уже гипотеза «из другой раскладки», оно проверяется `validateCorrection` (см. 4.5). Прошло — возвращается.

### 4.4. Шаг 2: CoreML

CoreML‑классификатор вызывается всегда. Если он предлагает «X из раскладки Y» с уверенностью > 0.45:

1. Алфавит слова должен совпадать с исходной раскладкой, иначе возврат к базовому решению.
2. Для всех гипотез с той же исходной раскладкой перебираются все варианты конвертации, и каждый проверяется `isValidConversion`:
   - русский предлог — всегда годится;
   - короткий результат (≤ 3 букв): W ≥ 0.80 и `F(результат) ≥ F(исходник) + 0.25`;
   - длинный: W ≥ 0.80 и W(результат) ≥ W(исходник) + 0.20, **или** `F(результат) ≥ F(исходник) + 0.25` и W ≥ 0.60, **или** триграммы результата ≥ 0.75 и лучше исходника на 0.15 при ненулевой частоте (или W ≥ 0.60).
3. Из прошедших берётся лучший по `quality`. Предложение CoreML заменяется другим, только если тот лучше на 0.12. Уверенность = max(CoreML, 0.90).
4. Если не прошёл ни один вариант, предложение CoreML отклоняется.

Если CoreML говорит «набрано правильно» с уверенностью выше базовой и > 0.70, берётся его ответ.

(На macOS 26 при включённой настройке при неуверенном базовом решении 0.40…0.70 спрашивается ещё Foundation Model, с такой же проверкой результата.)

### 4.5. Шаг 3: эвристика

Если слово в своём алфавите не похоже на слово (W < 0.80), пробуются гипотезы: для латиницы RU и HE, для кириллицы только EN, для иврита EN и RU. Каждая проверяется `validateCorrection`:

1. Из всех вариантов конвертации выбирается тот, что есть во встроенном лексиконе (или русский предлог).
2. Принимается, если:
   - результат во встроенном лексиконе, а исходник нет → уверенность 0.90;
   - W(результат) ≥ 0.80 и он лучше исходника по W на 0.20 **или по частоте** на 0.20 → 0.85;
   - короткое слово: `F(результат) ≥ 0.45` и лучше исходника на 0.25 → 0.85;
   - триграммы ≥ 0.75 и лучше на 0.15 при подтверждённой частоте → 0.80.
3. Если прошла ровно одна гипотеза, она и возвращается. Если ни одной или несколько, остаётся базовое решение.

### 4.6. Фильтр языков

В конце любое решение, которое затрагивает язык без включённой в macOS раскладки, превращается в «оставить как набрано» (`restrict`, строка 243).

### 4.7. Итоговая «улика» (`decisionEvidence`, строка 74)

Поверх `route` в автоматическом режиме действуют ещё три правила, по порядку:

1. **Короткое слово с заглавной буквы** (2–3 буквы, заглавная только первая: «Yj», но не «YJ» и не «yJ»). Если `route` сказал «набрано правильно», слово прогоняется ещё раз в нижнем регистре, и если для «yj» выходит исправление, берётся оно. Причина: проверка орфографии macOS принимает любое короткое слово с заглавной буквы за английское, поэтому «yj» становилось «но», а «Yj» оставалось. Заглавная при конвертации сохраняется: «Yj» → «Но», «Lf» → «Да».
2. **Оценочное решение**: дополнительно считается `scoredDecision`. Если основной путь сказал «набрано правильно», а оценочный уверенно (≥ 0.78) предлагает исправление для обычного слова, берётся исправление.
3. **Знак препинания русской раскладки в конце латинского слова** (`wrongLayoutPunctuationDecision`). Если латинское слово после конвертации в русский — слово со знаками только по краям, а само слово без них в русском известно (W ≥ 0.80), то:
   - если в исходнике есть «/», «&» или «^» (в русской PC‑раскладке это «.», «?» и «:»), решение `ru_from_en` с уверенностью 0.95, даже если голое слово — английское сокращение: никто не заканчивает английское слово на «/» («Lf/» → «Да.», «Lf&» → «Да?»);
   - иначе (например, «Lf?» → «Да,») нужно ещё, чтобы русское слово было во встроенном лексиконе, а голое латинское — не было во встроенном английском. Такой знак заканчивает предложение, и следующего слова, которое подтвердило бы язык, не будет.

Затем формируется:
- тип токена: обычное слово, короткое (≤ 3 букв), с пунктуацией, смешанное, техническое. Слово с пунктуацией только по краям («Вщту!», «Lf/») считается обычным или коротким. Для слова, набранного в чужой раскладке, краевыми знаками считаются и «/», «&», «^»;
- текст после конвертации (активная раскладка);
- отрыв победителя от второго кандидата.

## 5. Политика: заменять, подсказать или ждать горячую клавишу

`CorrectionDecisionPolicy.evaluate` (`Engine/CorrectionDecisionPolicy.swift`) по уверенности, отрыву, типу токена и типу приложения:

| Тип | Автозамена (сбалансированный режим) | Подсказка |
|---|---|---|
| Обычное слово, приложение даёт читать текст | уверенность ≥ 0.78 и отрыв ≥ 0.12 (до 18 букв) | ≥ 0.70 |
| Обычное слово, приложение текст не отдаёт | ≥ 0.88 и отрыв ≥ 0.16 | ≥ 0.74 |
| Короткое (≤ 3 букв) | ≥ 0.90 и отрыв ≥ 0.16 | ≥ 0.70 |
| Короткое из белого списка | ≥ 0.90 | ≥ 0.65 |
| С пунктуацией внутри, приложение даёт читать текст | ≥ 0.78 и отрыв ≥ 0.12, если после конвертации получилось слово (2+ буквы, остались только буквы или знаки только по краям) | иначе подсказка ≥ 0.70 |
| С пунктуацией внутри, приложение текст не отдаёт | ≥ 0.88 и отрыв ≥ 0.16 (до 18 букв), при том же условии | иначе подсказка |
| Одиночный знак препинания («.» после слова) | никогда | — |
| Смешанное, техническое, «набрано правильно» | никогда | — |

Слова со знаками внутри, которые в другой раскладке оказываются буквами («Yf;fk» → «Нажал», «Cgfcb,j!» → «Спасибо!»: «;» — это «ж», «,» — «б»), раньше в приложениях без доступа к тексту (Claude, Electron‑приложения) не исправлялись вовсе; теперь решаются как обычное слово.

Слова короче настройки «минимальная длина» (по умолчанию 2 буквы) только вручную (исключение — однобуквенные русские слова из раздела 3). В поле пароля только вручную. Консервативный режим поднимает пороги на 0.06, агрессивный опускает.

**Обучение.** При включённом обучении персональный профиль (`RiskController.demote`) может понизить решение в контексте (приложение, время суток, тип текста), где исправления часто отменяют:
- «автозамена» → «подсказка», если накоплено ≥ 4 единиц опыта и **даже оптимистичная** оценка доли оставленных исправлений (среднее + 1/√(опыт + 1)) ниже 0.70;
- «подсказка» → «горячая клавиша», если опыта ≥ 6 и оптимистичная оценка ниже 0.50.

Раньше бралась пессимистичная оценка (среднее − неопределённость, пороги 0.60 и 0.45), и нескольких оставленных исправлений без единой отмены не хватало: контекст, где оставляли 76 % исправлений (Заметки), уходил на горячую клавишу. Отменой исправления теперь считается только стирание Backspace‑ом исправленного слова целиком; раньше отменой считались любые три быстрых Backspace подряд, в том числе исправление опечатки в следующем слове.

## 6. Движок после роутера

1. **Быстрая дорога**: для обычных слов, коротких слов из белого списка, **коротких слов со знаками только по краям** («Lf/» → «Да.»: результат конвертации окончательный) и **слов, набранных через клавиши знаков**, если результат целиком есть в частотном словаре (см. п. 2), а также всегда, когда политика не «автозамена». Автозамена ставит конвертированный текст. Подсказка или ручной режим запоминают вариант для горячей клавиши. Если исправления нет, может появиться **подсказка транслитерации** («privet» → «привет»): слово из латиницы похоже на транслит, не является английским словом (проверка включает частотный словарь), а результат — русское слово.
2. **Слова со знаками внутри** («cj;fktyb.», «ghbdtn.rfr»):
   - Если слово исправляется, а его буквенное ядро после конвертации (без знаков по краям) есть в частотном словаре целевого языка, слово конвертируется **целиком** по быстрой дороге: «Yf;fk» → «Нажал», «Cgfcb,j!» → «Спасибо!». Если резать такое слово по знакам, куски конвертировались бы по отдельности («Yf;כל»).
   - Иначе сравниваются два кандидата.
     - **Целиком**: всё слово конвертируется, выбирается вариант раскладки с лучшей суммарной оценкой `fastTextScore` = сумма по словам max(частотная оценка, лексикон) по всем языкам.
     - **По частям**: слово режется на буквенные куски и разделители, каждый кусок прогоняется через роутер отдельно.
     - Целый вариант выигрывает, если он есть во встроенном лексиконе, **или если рядом со знаком внутри стоит кусок короче 2 букв, а целый вариант состоит только из букв**: одиночная буква не может быть отдельным словом, значит знак — это буква чужой раскладки («J,yjdb» → «Обнови», а не «J,нови»). Части выигрывают, если «.» или «,» стоит между двумя кусками по 2+ буквы, части сохранили этот знак, а целый вариант его «съел» (при уверенности < 0.9). В остальных случаях части должны быть лучше целого на 0.25.
     - Перед применением результат проверяет **верификатор** (`CorrectionVerifierAgent`): обратная конвертация должна дать исходник (иначе −0.10), исходник не должен быть настоящим словом (оценка ≥ 0.70 → штраф), результат не должен быть бессмыслицей (средняя оценка по словам < 0.10 → отказ), язык должен совпадать с языком предложения (иначе −0.15). Оценка слова здесь = max(частотная оценка, лексикон).
   - В приложении, которое не отдаёт текст, такое слово (если оно не «слово, набранное через клавиши знаков») автоматически не заменяется, самое большее показывается подсказка: его пришлось бы резать по знакам и перепечатывать вслепую.
3. **Стандартная дорога** (остальное): итоговая уверенность сравнивается с порогом (0.70, для коротких 0.58, для частых коротких слов иврита 0.30). Ниже порога слово может стать «отложенным» и исправиться задним числом, если следующее слово подтвердит язык. Выше порога выбирается вариант конвертации: первый, который есть во встроенном лексиконе, иначе первый. Для слов длиннее 3 букв его проверяет верификатор. Затем применяется политика риска.
4. Для коротких валидных слов в прозе («ну», «он») движок запоминает, во что они превращаются в других языках, если результат есть в лексиконе (или в частотном словаре, но после фильтра длины туда попадают только слова от 3 букв). Это позволяет исправить такое слово задним числом, если следующее слово покажет, что предложение на другом языке.
5. **Каскад на предыдущее слово** (`contextualCascadeCorrection`). Когда в приложении, которое отдаёт текст, слово заменено автоматически, а предыдущее слово было не длиннее 2 букв, оно тоже конвертируется в язык исправления, если результат — слово этого языка. Однобуквенный результат должен быть словом из списка однобуквенных (раздел 1): русская «с» перед английским словом не становится «c». Двухбуквенный должен быть во встроенном лексиконе или в частотном словаре. Раньше любой двухбуквенный буквенный результат принимался без проверки. Раскладка при этом переключается до замены, чтобы следующие буквы попали в новую раскладку.

Пока исправление применяется, нажатия пользователя придерживаются и отпускаются по порядку после замены, уже в переключённой раскладке. Раньше они попадали между буквами перепечатываемого слова или сразу после него, сверка поля не сходилась, и раскладка переключалась обратно.

В приложениях, где текст нельзя прочитать, замена делается «вслепую»: Backspace и перепечатка. Это допускается только для известных хостов, сразу после набора, для слова 1…18 букв (не короче минимальной длины, кроме однобуквенных русских слов из раздела 3) с уверенностью не ниже порога для «слепых» замен. Словом считается и токен со знаками только по краям, и токен, чьи знаки в другой раскладке стали буквами («Cgfcb,j!» → «Спасибо!»).

## 7. Что изменилось с подключением словарей (PR #4)

- «Слово существует» теперь проверяется по 200 тыс. слов на язык, а не только по системному словарю и ручному лексикону. Иврит, где системная проверка отключена, больше не держится только на лексиконе.
- В оценках `quality`, `isValidConversion`, `validateCorrection` и в верификаторе появилась ненулевая частотная составляющая. Частые слова выигрывают увереннее, редкие формы перестали быть «бессмыслицей».
- Сильнее защищено то, что набрано правильно: настоящее русское, английское или ивритское слово реже принимается за ошибку раскладки.
- Короткие (1–2 буквы) записи частотных списков не используются: для коротких слов поведение осталось прежним и держится на встроенном лексиконе.
- Фонетическая «Russian – QWERTY» больше не используется для английского текста, если она не ваша раскладка.

## 8. Что изменилось после PR #4

- **Сокращения и смайлики** в чужой раскладке («n/r/» → «т.к.», «Ж-)» → «:-)») исправляются сразу по точному списку (раздел 3).
- **Однобуквенные русские слова** в английской раскладке («Прочитай b» → «Прочитай и», «Привет. Z» → «Привет. Я») исправляются сразу, без ожидания следующего слова (раздел 3).
- **Короткие слова с заглавной** («Yj», «Lf» в начале предложения) решаются так же, как в нижнем регистре (раздел 4.7).
- **Знаки препинания русской раскладки в конце слова**: «Lf/» → «Да.», «Lf&» → «Да?», «Lf?» → «Да,». Знаки по краям переводятся по клавише, «/» в конце слова больше не делает его путём (разделы 3, 4.2, 4.7).
- **Слова с «ж», «х», «э», «б», «ю»**, набранные в английской раскладке («Yf;fk», «Cgfcb,j!», «J,yjdb»), конвертируются целиком, в том числе в приложениях без доступа к тексту (разделы 5, 6).
- **Раскладки с переставленными буквами** (фонетическая, Colemak, Dvorak) пробуются, только если включены в macOS (раздел 4.2).
- **Одиночный знак препинания** не исправляется никогда (раздел 5).
- **Каскад на предыдущее короткое слово** проверяет, что результат — слово (раздел 6).
- **Пауза** больше не обрывает слово; при задержанном Enter подсказка применяется сразу; если буфер оказался концом слова из поля, слово не трогается (раздел 2).
- **Обучение** понижает решения только там, где исправления действительно чаще отменяют, чем оставляют, а отменой считается только стирание слова целиком (раздел 5).

Почему каждое слово получило свой исход, видно в подробном журнале («Подробный журнал» в настройках): движок записывает цепочку отметок вида `policy=autoApply,learning=suggestHint,risk=suggestHint,fast_lane` (`DecisionTrail`, `Engine/CorrectionEngine+Planning.swift`).

## 9. Пример: «ghbdtn» в Slack с русской PC‑раскладкой

1. Пробел → `correctText("ghbdtn")`.
2. Не сокращение, не одна буква, не код. Жёсткие правила роутера не сработали (латиница, не технический токен, не в белом списке).
3. `scoredDecision`: «как набрано» по‑английски: W = 0 (нет ни в одном словаре), F = 0, триграммы низкие. Гипотеза `ru_from_en` → «привет»: W = 1 (лексикон, частотный словарь, орфография), F ≈ 0.66, триграммы высокие; «сильное принятие». `quality` превышает «как набрано» намного больше запаса 0.70 → решение `ru_from_en`, уверенность 0.95.
4. Тип токена: обычное слово, отрыв большой. Политика: 0.95 ≥ 0.78 → автозамена.
5. Слово заменяется на «привет».

## 10. Пример: «privet»

1. «Как набрано» по‑английски: слова нет в словарях.
2. Через русскую PC‑раскладку получается «зкшмуе», такого слова нет ни в одном словаре, гипотеза не проходит. Через фонетическую раскладку конвертация не пробуется, потому что она не включена в macOS.
3. Исправления нет. Детектор транслитерации видит, что «privet» есть в его коротком списке, не является английским словом, а «привет» — русское слово → показывается подсказка «привет», которую можно применить вручную.

## 11. Пример: «Lf/» перед отправкой сообщения

1. Enter → Enter задерживается, `correctText("Lf/")`.
2. Не сокращение («да.» не в списке), не одна буква. Детектор намерения не считает «Lf/» путём: «/» только в конце после букв.
3. Роутер: «Lf» — короткое слово, проверка орфографии принимает его за английское, `route` говорит «набрано правильно». Правило заглавной (4.7, п. 1) к «Lf/» не применяется (в токене не только буквы), но срабатывает правило знака в конце (4.7, п. 3): «Lf/» → «Да.», «да» — русское слово, в токене есть «/» → `ru_from_en`, уверенность 0.95.
4. Тип токена: короткое слово со знаком по краю → быстрая дорога. Политика для короткого: 0.95 ≥ 0.90 → автозамена.
5. Слово заменяется на «Да.», раскладка переключается на русскую. Задержанный Enter не отправляется: сообщение уйдёт по следующему Enter, уже исправленным.
